# التشغيل والنسخ والاستعادة

هذه النشرة تضيف ترابط الخطة والزيارة والتحصيل ودليل أعمال جاهز، وتصلح الجلسات وتعارض الكراسي والعمليات المالية المتزامنة والنسخ الاحتياطي. لا تكفي الاختبارات المحلية وحدها لاعتماد الاستخدام السريري؛ يلزم اختبار قبول من المركز على نسخة تجريبية.

## قبل النشر

1. خذ نسخة PostgreSQL ونسخة كاملة من قرص المستندات قبل تغيير النشرة القديمة، واحتفظ بمعرّف النشرة السابقة. لا تعتمد على نسخة SQL القديمة وحدها لاستعادة الأشعة.
2. جرّب النشرة على قاعدة مستقلة وتخزين مستقل. التغييرات إضافية، ويحفظ الدليل أسعار المركز الحالية. دخول الموظفين الحالي يتطلب إعادة تسجيل الدخول بسبب إضافة إصدار الجلسة.
3. اضبط `SESSION_SECRET` عشوائيًا (32 حرفًا فأكثر)، و`DOCUMENTS_DIR` على قرص دائم مثل `/data/documents`. احذف `SETUP_TOKEN` بعد التهيئة.
4. الاتصالات الخارجية بقاعدة البيانات تتحقق من شهادة TLS افتراضيًا. استخدم `PG_SSL_CA` لشهادة سلطة خاصة. اتصال Railway الداخلي أو localhost لا يحتاج TLS افتراضيًا؛ `PG_SSL_MODE=disable` للاتصال الخاص المقصود فقط. لا تعطّل التحقق من الشهادة على الإنترنت.
5. حد تسجيل الدخول 10 محاولات لكل حساب خلال 15 دقيقة، محفوظ في PostgreSQL ويشمل المحاولات المتزامنة. لا تفعّل `TRUST_PROXY=true` إلا إذا كانت المنصة تضبط آخر عنوان في `X-Forwarded-For` بنفسها؛ عندها يضاف حد 60 محاولة للمصدر.
6. فعّل حماية `main` بمراجعة طلب الدمج ونجاح `Verify release / verify` ومنع الدفع المباشر. إعداد الحماية من GitHub مطلوب؛ وجود ملف CI وحده لا يفعّلها.

## فحوص النشرة

```sh
npm ci
npm run typecheck
npm test
# قاعدة اختبار محلية بصلاحية CREATE DATABASE، وليست بيانات العيادة
npm run verify:all
npm run build
npm run verify:http
```

اختبارات التكامل تنشئ قواعد مؤقتة وتحذف قواعدها فقط. لا تنفّذها بحساب قاعدة الإنتاج. يستخدم البناء Webpack؛ الأمر `build:turbo` متاح للتجربة فقط حتى يُحل تعطل عامل PostCSS الذي ظهر في Windows.

اختبار القبول: أضف مريضًا تجريبيًا، جهّز أسعار الأعمال، أنشئ خطة عصب ووتد وبناء، وثّق موافقته، نفّذ العصب في زيارة، اقبض دفعة جزئية، ثم نفّذ الوتد والبناء بزيارة ثانية. تحقق من البنود الثلاثة والفاتورتين والسند والمديونية وجرد الصندوق. اختبر المستخدم الطبيب والاستقبال كلًا بصلاحياته.

## النسخة الكاملة

من الإعدادات ← التصدير ← النسخة الكاملة، أو من نسخة المستودع المطابقة للنشرة وبنفس اتصال قاعدة البيانات وقرص المستندات:

```sh
npm ci
npm run backup:full -- /secure-backups/aqlan-2026-08-31.tar.gz
```

تشمل `database.sql` وكل ملفات المستندات الأصلية، بما فيها المخفية، وفهرس `manifest.json` وبصمات SHA-256. يستخدم SQL وقائمة الملفات لقطة واحدة، وتُكتب علامة اكتمال وفهرس في نهاية النسخة. تنتهي العملية بخطأ عند غياب ملف أو تلفه، ولا ينشر أمر CLI ملفًا نهائيًا ناقصًا. النسخة SQL وحدها لا تحتوي ملفات الأشعة؛ أرشيف المستندات المسمّى بأسماء المرضى مناسب للتصفح وليس بديلًا عن النسخة الكاملة.

جدولة التشغيل تكون على مضيف موثوق يصل إلى PostgreSQL **وقرص المستندات نفسه**، باستخدام جدولة النظام/المنصة. صورة تشغيل التطبيق المستقلة لا تتضمن أدوات التطوير، لذلك استخدم عامل نسخ من المستودع مع اعتمادياته أو نقطة تنزيل النسخة المحمية. لا تضع كلمة مرور الموظف في جدولة HTTP. لم يُنشأ جدول نسخ خارجي تلقائيًا في هذه النشرة.

انسخ النسخة المشفرة يوميًا إلى مكان خارج قرص التطبيق، واحتفظ بنسخ يومية وأسبوعية وفق سياسة المركز. راقب فشل المهمة وعمر أحدث نسخة. احتفظ بمفتاح التشفير منفصلًا واختبر الاستعادة شهريًا. صلاحيات الملفات المحلية لا تعادل التشفير.

## تجربة الاستعادة

أوقف تطبيق الهدف. استعد إلى **قاعدة جديدة ومجلد مستندات جديد فارغين**، ومن نسخة مستودع تطابق إصدار الأرشيف. احفظ النسخة الأصلية ولا تفك أرشيفًا من مصدر غير موثوق.

```sh
mkdir recovery
tar -xzf /secure-backups/aqlan-2026-08-31.tar.gz -C recovery
# اضبط DATABASE_URL وDOCUMENTS_DIR للهدف الجديد، ثم:
npm run restore:full -- recovery
```

يتحقق الأمر من بصمات SQL والملفات وحدود المسارات قبل النسخ. يرفض استبدال قاعدة أو مجلد فيه بيانات، وينفذ SQL في معاملة واحدة. إذا فشل إدخال SQL بعد نسخ الملفات، قد تبقى ملفات في مجلد الهدف؛ استخدم هدفًا جديدًا للمحاولة التالية ولا تحذف ملفات إنتاج. أعد تشغيل التطبيق بسر جلسات جديد، ثم تحقق من عدد المرضى والفواتير والسندات والأرصدة ومن فتح مستند عربي وآخر مخفي ومن صدور أرقام جديدة غير مكررة.

أرشيف النسخة يحتوي بيانات صحية ومالية وكلمات مرور مجزّأة؛ عامله كبيانات سرية. لا ترفعه إلى Git أو ترسله دون تشفير. لا تُلغِ نشرًا بقاعدة بيانات أقدم دون مراجعة الحركات التي أضيفت بعد النسخ.

## حدود متبقية خارج الكود

حماية الفرع، النسخ الخارجية المجدولة والتنبيه، إعدادات TLS والقرص الدائم، وموافقة الطبيب والمحاسب على التشغيل الفعلي تحتاج التحقق في حساب الاستضافة والمركز. لم تُنشر هذه التعديلات إلى الإنتاج تلقائيًا.
