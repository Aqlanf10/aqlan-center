نجح فحص ما بعد النشر والتشغيل اليدوي، ثم نجحت أول ثلاثة تشغيلات مجدولة التي تمت مراجعتها. هذا يثبت أن الجدولة والفحص يعملان، مع بقاء حدود تنبيهات GitHub أدناه.

تنبيهات البريد تعتمد على إعدادات إشعارات GitHub Actions في حساب المالك؛ لم يُضبط بريد أو webhook خارجي. المراقبة المجدولة في GitHub قد تتأخر ولا تُعد مراقبة لحظية. الفحص لا يثبت وجود نسخة احتياطية حديثة.

- يجب مراجعة أسماء الأعمال والأسعار وإقرار سيناريو التشغيل من الطبيب والمسؤول المالي قبل الاعتماد اليومي الكامل.

## تفعيل نسخ Railway بعد تجديد الصلاحية

من المشروع → كل خدمة (`web` و`Postgres`) → Backups، فعّل اليومي والأسبوعي والشهري، ثم أنشئ نسخة فورية وتحقق من نجاحها. أو باستخدام Railway CLI الحديث والمشروع والخدمة المحددين صراحة:

```sh
railway postgres pitr schedule set --daily --weekly --monthly --project 69ad4134-ac96-4c4d-9cb1-17cfef5bb012 --environment production --service Postgres
railway postgres pitr schedule set --daily --weekly --monthly --project 69ad4134-ac96-4c4d-9cb1-17cfef5bb012 --environment production --service web
```

نسخ الأقراص لها كلفة تخزين إضافية حسب الاستخدام، وتبقى مرتبطة بالمشروع. وفق توثيق Railway، حذف القرص نهائيًا يمحو نسخه، لذلك يلزم أيضًا الاحتفاظ بأرشيف كامل مشفر خارج قرص التطبيق واختبار استعادته دوريًا. لا تُجرّب الاستعادة فوق الإنتاج.
